# AROM:D · 아롬디의 차곡차곡 정산노트

실행 링크: https://arodv.github.io/aromd-settlement/

## 앞으로 HTML 업데이트하기

1. Codex에게 최신 **index.html** 파일을 받습니다.
2. [파일 업로드](https://github.com/arodv/aromd-settlement/upload/main)를 엽니다.
3. 받은 `index.html`을 끌어 놓습니다. 파일명은 반드시 `index.html`로 유지하세요.
4. 아래의 **Commit changes**를 누릅니다. 기존 index.html이 새 버전으로 바뀝니다.
5. 약 1~2분 후 실행 링크를 새로고침합니다. GitHub Actions에서 배포 완료를 확인할 수 있습니다.

GitHub Pages는 main 브랜치의 루트 폴더를 사용합니다. 다른 설정을 바꿀 필요 없이 index.html만 교체하면 됩니다.

입력 기록은 각자의 브라우저에 저장됩니다. 기기 간 자동 동기화는 하지 않습니다.

## 정산 검증 방식

- 2026년 가을 회사 정산율표의 A/B/C/OPTION 요율, 쌍수별 차량비, 쌍당 매출 보너스를 사용합니다. A/라텍스·A/꿀집과 B/꿀집·B/라텍스 입력은 각각 유지합니다.
- 쇼핑매출과 **옵션 인정매출**을 합산해 쌍당 매출 및 요율 구간을 정합니다. 옵션 수수료는 별도 **옵션 정산매출**로 계산합니다.
- T/M 원본의 달러 환산 환율, 샵/옵션 수수료 정산 적용환율, 원화 환율을 구분합니다. 정산 적용환율은 차감 후 최종값을 입력하며 추가로 1바트를 빼지 않습니다.
- 원본 바트를 입력한 경우 달러 환산 소수는 계산에 보존합니다. 기본값은 항목별 1바트 반올림이며 0.01바트 방식도 선택할 수 있습니다.
- 상조회비는 쌍당 200바트를 항상 자동 공제합니다. 회사 실제 지급액을 바트로 입력해 비교할 수 있습니다. 회사 지급액은 예상 정산액을 만드는 입력으로 사용하지 않습니다.
- 인정률과 원가 공제액은 회사 제공값을 입력합니다. 회사 내부 산출 과정은 검증 범위에서 제외하고, 해당 값 이후의 요율·수수료·공제·지급액을 검증합니다.
- 이전 버전 기록은 저장된 결과를 그대로 읽습니다. ‘새 기준으로 검토’는 원본을 유지하고 별도 검토본을 만듭니다. 기존 4분류 기록의 A/B 매장은 재분류 시 확인해야 합니다.

업데이트 전에 저장 기록에서 백업을 내보내는 것을 권장합니다. 이전 버전은 새 형식의 백업을 읽지 못할 수 있으므로 업데이트 후 기록을 저장했다면 구버전으로 돌아가기 전에 다시 백업해 주세요.

같은 사이트 주소와 같은 브라우저를 사용하면 이전 기록을 계속 읽습니다. 다른 주소·기기·브라우저로 옮길 때는 백업 내보내기/불러오기를 사용하세요.
